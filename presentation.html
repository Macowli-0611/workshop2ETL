"A Data Engineer does not build scripts. A Data Engineer designs systems."

"Reliable pipelines do not assume data is correct. They verify it."

Section 6.8 • Integration Contract

Transformation & The Integration Contract

A formal contract specifying matching keys, cardinality, text normalization, and unmatched record policies.

🧼 Evidence-Based Cleaning Preprocessing
  • Duplicate Pruning: Removed 450 pure duplicate rows on (track_id, track_genre) identified during profiling.
  • Corrupted Outlier Filter: Filtered row 65,900 with duration = 0 ms and NaN track metadata.
  • Textual Normalization: Stripped punctuation, converted to lowercase, and trimmed redundant whitespace.
  • Artist Decomposition: Extracted primary artist by splitting on ; for Spotify and collaborative tokens (featuring, &, with) for Grammys.
🤝 The Integration Contract Data Contract
  • Matching Keys: (clean_track_name, clean_primary_artist).
  • Cardinality: N-to-1 (multiple genre tracks map to single award honor).
  • Unmatched Catalog Rows: Preserved via Left Join with is_grammy_winner = False, award_count = 0, mapped to default dimension keys (SK = 0).
  • Result: 113,549 prepared load-ready tracks with 475 confirmed Grammy-winning tracks (0.42% of catalog).
Section 6.4 & 6.10 • Dimensional Modeling

Star Schema Data Warehouse in PostgreSQL

Requirements-driven dimensional model hosted in dw_music_analytics (SQLite strictly rejected).

⭐ Fact & Dimensions Grain PostgreSQL 16
  • Fact Table: fact_music_performance
  • Grain: One row per audio track, catalog genre, and award event.
  • Surrogate Keys: SERIAL autoincrementing integers across all 5 dimensions.
  • Default Dimension Records: SK = 0 created for dim_time ('Unknown') and dim_grammy_category ('No Nomination / Not Applicable') for non-awarded catalog tracks.
  • Safe Rerun Invariant: CONSTRAINT uq_fact_grain UNIQUE (track_sk, genre_sk, time_sk, category_sk).

🔒 Architectural Mechanism Atomic Upsert
INSERT INTO fact_music_performance (...) SELECT ... FROM temp_prepared_staging ON CONFLICT (track_sk, genre_sk, time_sk, category_sk) DO UPDATE SET popularity = EXCLUDED.popularity, danceability = EXCLUDED.danceability, is_grammy_winner = EXCLUDED.is_grammy_winner, loaded_at = CURRENT_TIMESTAMP;
